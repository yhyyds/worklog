# Worklog 1.2：历史未完成任务

## 查看范围

从侧栏打开“待办与历史”时，默认进入“历史未完成”。列表包含今天以前处于未开始、进行中、等待或阻塞状态，并且仍属于原日期计划的任务。

以下内容不会重复出现：

- 已完成、已取消或已标记延期的旧实例；
- 已收入待办箱或被长期目标安全移除的实例；
- 同一永久任务已经存在较新可见实例的旧安排。

父任务与仍未完成的直接子任务合并展示。如果父任务已经完成而子任务仍未完成，子任务会作为可单独安排的事项显示。

## 重新安排

用户选择今天或未来日期后，可以重新安排一项历史任务。系统在单一 SQLite 事务中：

1. 再次确认来源仍是历史未完成任务；
2. 确认目标日期没有相同永久任务；
3. 为目标日期创建新的每日实例，重新生成当天编号；
4. 通过 `carry_from_instance_id` 记录来源实例；
5. 更新原实例的延期投影，并在来源日期和目标日期各追加一条事件。

任一步失败都会整体回滚。原任务 UUID、原日期实例、专注记录、工作想法和既有事件不会删除或改写。父任务重新安排时只带上仍未完成的子任务，已完成子任务保持原样。

重复目标任务会继续显示，方便发现遗漏，但按钮保持禁用并提示回到“成长”修改日期。这样可以避免绕过长期目标的计划次数和周报统计规则。

## 与待办箱的区别

- “历史未完成”处理已经有过去日期、但遗漏处理的任务。
- “待办箱”处理暂时没有日期的任务，以及主动从今天收纳的任务。

任务卡上的“待办箱”按钮仍直接打开收纳页；侧栏“待办与历史”默认打开历史页。
