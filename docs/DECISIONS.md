# Worklog 决策记录

本文件记录迁移后不能仅从代码表面推断的产品与工程决定。

## D-001 本地优先

SQLite 是任务、时间线、番茄钟和设置的结构化事实源。应用不依赖云服务即可工作，任何新功能不得默认上传用户工作内容。

## D-002 Obsidian 是投影与编辑入口

Obsidian Markdown 用于查看、补充和回顾，不复制替代 SQLite 的结构化事实。应用只能更新带版本标记的受管理区块，区块外的人工内容必须原样保留。

## D-003 不可变事件

任务、专注、暂停、切换和工作想法通过追加事件记录历史。不得修改或删除既有领域事件来伪造当前状态；界面和日记通过投影降噪。

## D-004 两级任务与编号

父子任务最多两级。永久 UUID 跨日不变；当天显示编号仅用于当天沟通和回顾，顺延到次日时重新生成。

## D-005 主页面稳定

“我的一天”始终是主页面和导航选中项。随笔、Obsidian、设置只通过弹窗打开，避免主页面标题与上下文来回切换。

## D-006 专注记录约束

专注目标只显示一级任务，避免子任务过多。暂停必须填写原因。切换专注目标要记录切换前后的编号和标题。

## D-007 数据迁移必须可恢复

变更本地数据库目录时，先创建一致性副本并验证可打开，再切换指针。旧数据库不删除。Obsidian 写入前备份，文件替换采用安全的临时文件流程。

## D-008 日记路径由用户决定

不强加“工作日志”目录。日记根目录可等于 Vault 根目录或其内部目录，最终路径为 `YYYY/YYYY-MM/YYYY-MM-DD.md`；必须阻止 Vault 外路径和符号链接越界。

## D-009 0.9.1 是新的迭代起点

用户明确要求后续工作基于 `0.9.1`。虽然 Git 历史中存在 `0.9.2`，它只用于历史保留和需求参考，不作为代码来源。

## D-010 Obsidian 折叠采用原生嵌套列表

`0.9.1` 使用 `<details>` / `<summary>`。从该基线独立实现的本机 `0.9.2` 改为父级时间段记录加一个制表位缩进的子事件，父子之间无空白行，让 Obsidian 原生识别并折叠。

## D-011 Windows 提供双安装包

Windows 发行同时提供：

- 不内置 WebView2：体积小，目标电脑需已有或联网安装 WebView2。
- 内置离线 WebView2：体积大，可在离线环境完成依赖安装。

两个安装包命名明确包含 `no-webview2` 与 `with-webview2`，并生成 SHA-256；不能让用户仅凭体积猜测差异。

## D-012 用户数据不随卸载删除

安装、升级和卸载脚本不得主动清理数据库、应用数据目录或 Vault。任何清理功能都必须由用户明确触发并说明影响。

## D-013 关闭行为由桌面后端决定

设置允许“直接退出”或“隐藏到托盘”。关闭请求由 Rust 桌面层读取 SQLite 设置并执行；前端不再无条件拦截窗口关闭。读取设置失败时保守地隐藏到托盘，避免正在运行的专注意外中断。

## D-014 打卡是次日复盘，不是实时签到

每天到工位后只结算前一日。记录同时保存归属日期和实际复盘时间；周报按归属日期统计。前置依赖失败不会删除原始完成事实，而是把后续项目标记为“已做到但未有效达成”。重复事项不顺延。

## D-015 长期目标采用滚动式规划

长期目标拥有自定义周期，但只要求详细规划离当前最近的阶段。阶段先保存自由随想，再拆成必须/附加、一次性/重复计划。进度以必须事项为 100% 分母，附加事项允许把进度推高到 100% 以上。

## D-016 周报使用本地规则和个人基准

周报不调用 AI。指标优先与上周比较，并在有足够数据时使用最近八个有效周的中位数作为个人基准。系统判断和文学引语分开：判断精确描述数据，引语必须记录作者、作品和来源，不为贴合指标伪造署名。

## D-017 图片导出采用独立画布

周报 PNG 由固定宽度、内容自适应高度的独立 Canvas 模板渲染，而不是截取应用窗口。包含习惯、任务和专注明细；长标题换行，不静默裁切。导出只写入用户通过系统对话框选择的绝对 PNG 路径。

## D-018 周报明细与界面文案

周报展示逐习惯的七日状态、跨周连续天数、截至报告日期的历史最长、本周最长、中断次数和上周同期完成记录。未回顾不等于未完成，也不跨未知日期拼接连续天数；中断只计确认完成后紧接确认失败的一次转换。前置未完成单独标识，保留自身已做的事实。

界面使用直接的动作、名称和数字，移除“通过依赖”“规则生成，不使用 AI”等实现说明，以及无信息量的安慰/宣传文案。必要的安全提示保留；统计口径放进可展开说明。

用户取消每轮完整 demo 验收，改为自行试用反馈；自动化测试与构建检查继续。

## D-019 分享数据先过滤后统计

1.1 分享周报使用独立白名单 DTO 与独立图片渲染器，不把个人完整周报传入分享模板。公开分类可以显示名称与颜色；逐项名称还需单独授权。匿名分类仅计入整体统计，不输出分类或占位事项明细。排除分类连同目标关联的子任务与专注片段一起排除；历史同期按相同规则重算，引句不读取私人周报缓存。分享范围变化后对比也随之重算，不伪装成不可修改的审计记录。

## D-020 目标任务排期保留历史

执行安排关联永久任务 UUID。一次性顺延不创建新的目标完成次数；重复任务及子任务禁止顺延/待办箱绕过。已有手动计数保留，发生排期后改由每日任务状态计数，避免重复。删除目标任务保留已开始/历史安排与事件，只移除无执行记录的今天及未来安排；目标进度分母随删除而变化。周报分类目标完成率按本周每日安排统计，目标卡按全部计划次数统计，两者不能混称。
