# Worklog 架构基线

## 目标

Worklog 是 Windows 本地优先桌面应用。核心数据由应用管理，Obsidian 用于查看、补充与回顾。架构首先保证数据安全、事件一致性和后续模块可替换性。

## 结构

- **表示层**：React 页面与组件，只处理交互和展示。
- **应用层**：用例编排、输入校验、事务边界和查询模型。
- **领域层**：任务编号、跨日、番茄钟、事件降噪等纯规则。
- **端口层**：Repository、Clock、Notification、MarkdownWriter 接口。
- **基础设施层**：SQLite、Windows 通知、Tauri IPC、Obsidian 文件系统适配器。

依赖方向始终指向领域层。React 不直接拼 SQL，领域规则不依赖 Tauri。

## 写入链路

每个用户命令在一个 SQLite 事务中完成：

1. 校验命令与领域不变量。
2. 更新任务、计时器等当前状态。
3. 追加不可变领域事件。
4. 标记回顾投影和 Markdown 同步为 dirty。
5. 提交事务。

原始事件完整保留；“今日记录”读取降噪后的投影，而不是直接展示全部事件。

## 模块边界

- Day Planning：每日实例、四象限、显示编号、跨日。
- Timeline：不可变事件、聚合和可见性。
- Focus：会话、阶段、任务分段、恢复。
- Work Entry：进度/想法/决定/阻塞/结果及三级回顾等级。
- Essay：Markdown 随笔和 Obsidian 链接。
- Sync：受管理区块、原子写入、备份与冲突。

## 关键决策

- 模块化单体优先于微服务；桌面本地应用无需引入分布式复杂度。
- SQLite 是内部事实源，Markdown 是可读投影。
- 任务永久 UUID 不变；每日显示编号在跨日时重新生成。
- 计时使用目标结束时间计算，应用休眠或重启后可恢复。
- Windows 专属能力集中在 Rust 适配器中，便于测试和未来移植。
