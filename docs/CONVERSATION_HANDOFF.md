# Worklog 对话决策交接摘要

这是从产品讨论中提炼的可执行记录，用于让新的本地 Codex 理解需求演进。它不能替代原始会话归档，但包含继续开发所需的核心约束。

## M1–M3：基础与 Obsidian

- 建立 Windows 本地优先的四象限日程应用。
- 任务拥有永久 ID 和当天编号，允许两级子任务。
- SQLite 保存结构化事实，事件以追加方式保留。
- Obsidian 日记只替换受管理区块，保留人工内容。
- 写入前备份、原子替换，并阻止路径穿越和 Vault 越界。

## M4–M6：日终、随笔与完整番茄钟

- 日终只顺延未完成任务，父任务内已完成子任务不复制。
- 加入 Vault Markdown 浏览、搜索、编辑、预览和 Wiki Link。
- 番茄钟升级为后台状态机，包含短休息、长休息、托盘、通知和快捷键。
- 自动机械事件不应污染每日回顾。

## M7–M8：发行、路径与集中设置

- 开始提供 Windows NSIS 安装包。
- 删除日记路径中固定的“工作日志”，用户自己选择根目录。
- 修复左侧导航按钮无事件绑定的问题。
- 左侧入口收敛为“我的一天、随笔、Obsidian、设置”。
- “我的一天”持续承载任务、专注和工作想法；其他入口打开弹窗。
- 设置集中管理番茄钟、字号、数据库目录、Obsidian 工作区和日记根目录。
- 数据库迁移后即时切换，旧数据库保留。

## M9：使用细节

- 父任务、子任务均可修改标题和当天时间。
- 完成项移动到所在列表底部，但编号和永久 ID 不变。
- 四象限固定高度并独立滚动，每个象限右上角有快捷新增按钮。
- 字号支持调整。
- 修改番茄钟时长后，空闲计时器立即刷新。
- 暂停番茄钟必须填写原因。
- 专注只选择一级任务。
- 切换专注任务必须写入时间线。
- `0.9.1` 修复父子任务完成勾选标记的视觉居中问题。

## 当前未完成的用户要求

用户要求从 `0.9.1` 重新迭代：

1. Obsidian 不需要 `<details>` / `<summary>`。
2. 每轮专注使用父级时间段记录。
3. 时间轴事件缩进一格，并与父级记录之间没有空白行。
4. 依靠 Obsidian 原生嵌套关系实现折叠。
5. 打包两份安装程序：不含 WebView2，以及包含离线 WebView2。

## 沟通偏好

- 用户希望直接完成实现、测试和打包，而不是只给理论方案。
- 版本基线和打包类型必须明确，不能模糊表述。
- 数据安全优先，任何迁移都要求无信息损失。
- 最终交付应给出 PR、精确提交、测试结果和可下载产物。

## 1.2：历史未完成任务

- 左侧入口改为“待办与历史”，侧栏打开时默认显示历史未完成；任务卡上的“待办箱”仍进入收纳页。
- 历史范围为今天以前仍未完成、未被收纳/移除、且没有较新实例的任务。
- 可以重新安排到今天或未来；永久 UUID、原实例和不可变事件保留，新日期重新编号。
- 父任务携带仍未完成子任务，完成子任务不复制；重复目标任务只能在“成长”中改期。
