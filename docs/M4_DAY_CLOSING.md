# M4：日终收尾与跨日顺延

## 目标

日终收尾不是机械复制所有未勾选事项，而是一次显式确认：

1. 回顾完成、等待和阻塞数量。
2. 默认勾选所有未完成且未取消的候选事项。
3. 用户可以逐项取消顺延。
4. 确认后在单个 SQLite 事务中完成状态更新、次日实例生成和事件追加。
5. 如果已配置 Obsidian，同步今天的最终 Markdown 日记。

## 跨日规则

- 已完成和已取消事项永不顺延。
- 父任务和子任务分别选择；已完成子任务不会随父任务复制。
- 子任务被选中而父任务未选中时，子任务在次日提升为顶级事项。
- 任务永久 ID 不变；次日实例 ID 和显示编号重新生成。
- 次日已有任务时，顺延事项从当天现有最大编号后继续分配。
- 等待和阻塞状态保留；进行中、未开始和延期状态在次日统一为未开始。
- 工作时间段不自动复制，避免把昨天的时间安排误当作今天的承诺。
- 有活动番茄钟时拒绝收尾；同一天只能成功收尾一次。

## 事务一致性

一次确认在同一事务内：

- 写入次日任务实例及 `carry_from_instance_id`。
- 更新源日实例的延期状态。
- 追加源日 `day.closed` 事件。
- 追加次日 `day.carryover_received` 事件。
- 写入 `day_closures` 防重记录。

任何一步失败都会整体回滚。
