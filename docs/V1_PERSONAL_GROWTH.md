# Worklog 1.0 个人成长系统（开发中，尚未完成发行验收）

## 范围

1.0 把 Worklog 从单日工作记录扩展为本地个人成长系统，同时保持 SQLite 为事实源、Obsidian 为安全投影。

## 昨日打卡

- 打卡只在次日到工位后复盘，不提供实时提醒或延迟签到。
- `occurrence_date` 是行为归属日期，`reviewed_at_utc` 是实际复盘时间。
- 每个日期只能结算一次；未回顾日期在周报中显示待回顾，不当作失败；今天及未来不能提前结算。
- `raw_completed` 保存事实，`effective_completed` 保存依赖结算结果。
- 一个打卡只有在自身完成且所有直接、间接前置打卡均有效完成时才算有效。
- 停用打卡不删除历史；停用日期之前仍参与历史统计。

## 长期目标

- 目标有自定义天数周期。
- 每个阶段包含日期范围和自由 Markdown 随想。
- 随想由用户整理成一次性或重复、必须或附加的执行项。
- 重复项通过目标次数表达周期内的独立发生次数，未完成次数不自动滚入下一周期。
- 进度公式：`(已完成必须次数 + 已完成附加次数) / 必须总次数`。
- 必须全部完成为铜杯；再完成部分附加为银杯；全部计划完成为金杯。

## 一周小笺

- 一周按周一至周日统计任务、专注、有效打卡和长期目标。
- 本周进行中时，与上周相同天数比较；最近八周中有数据的同期用于中位数基准，至少三个有效样本才启用投入/产出提醒。
- 任务按末级事项统计，取消项排除；待办箱未完成项不进入日计划分母。没有数据不推断为低效率。
- 长期目标暂时只在当前周展示即时进度，历史快照尚待实现。
- 分析情景目前包括稳定推进、强势完成、重新恢复和高投入低产出调整。
- 引语完全离线，逐条保存作者与作品。系统观察不是名人引语，二者不混写。
- 同一周重复生成保持同一句；优先排除最近 26 周使用过的引语。
- PNG 宽 1200 像素，高度按习惯和任务明细自动计算，写入路径必须由用户选择。
- 每个习惯展示七日记录、连续完成、本周最长、历史最长、中断次数和上周同期。前置项未完成与自身未完成分开显示；待回顾不推断为中断。
- 增加专注轮次、平均/最长时长、暂停与切换次数、每日表格、四象限分布、已完成/未完成事项与近四周同期对比。

## 待办箱

- 无日期收集新任务；现有任务可收入待办箱，父任务连同子任务收纳。
- 永久任务 ID、原始事件、专注和完成状态保留；已完成事实不因收纳而清零。
- 收纳会移除对应日期的安排归属，日记仍保留收纳事件；重新安排时取消原来的固定时段。
- 支持安排到今天或未来日期；重复安排会拒绝并整体回滚。单独收纳的子任务排期后成为一级任务。
- 正在专注的任务需要先结束专注，不能留下失联的计时器。

## 后续待办与试用方式

- 长期目标当前执行项仍是次数计数器，尚未完成按日发生、先后依赖、一次性顺延及真实循环逻辑；不可按完整功能发布。
- 引语库当前仅 40 条；几百条引语扩容、出处逐条核验及情景匹配仍待完成，不应宣称已核验。
- 实机关闭/托盘、Obsidian 锁占用和并发修改、完整计时生命周期、周报视觉与 PNG 检查尚未验收。
- 用户已取消每轮完整 demo 要求；当前保留自动化测试与编译检查，由用户实际试用反馈。可选演示模式不影响正式数据。
- 每次交付以重新构建的双安装包和 SHA-256 清单为准；1.0 尚有上述功能待完善，不将试用版描述为功能全部完成。

## 数据安全

- 迁移只新增表，不删除或改写旧表。
- 日记写入仍先备份、再通过临时文件安全替换；占用时重试，失败时保存状态。
- 重新生成历史日记只替换 `worklog:managed` 区块，区块外文本原样保留。
